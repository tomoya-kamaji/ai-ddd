# シナリオ記述（セミナー予約システム）

## UC1: 会員がセミナーに申し込む

- アクター: 会員
- 事前条件: 会員登録済み、セミナーが公開済み
- 事後条件（成功時）: 申込が「申込済」状態で作成される

### 基本フロー
1. 会員がセミナー詳細画面を開く
2. 会員が「申し込む」を押す
3. システムが定員・重複申込を確認する
4. システムが申込を「申込済」状態で作成する

### 代替フロー
- 3a. 定員に空きがない場合 → キャンセル待ちとして受け付ける（**対象スコープ外・将来対応**。ただし「定員に達している場合は申込不可」というルール自体はドメインモデルに含める）

### 例外フロー
- 3b. すでに同じ会員が同じセミナーに申込済みの場合 → エラーを返し、申込を作成しない

---

## UC2: 会員が申込をキャンセルする

- アクター: 会員
- 事前条件: 対象の申込が「申込済」状態で存在する
- 事後条件（成功時）: 申込が「キャンセル済」状態になる

### 基本フロー
1. 会員が自分の申込一覧からキャンセル対象を選ぶ
2. 会員が「キャンセルする」を押す
3. システムが開催日までの残り日数を確認する
4. システムが申込を「キャンセル済」状態にする

### 例外フロー
- 3a. 開催日の3日前を過ぎている場合 → エラーを返し、キャンセルできない
- 3b. すでに「キャンセル済」状態の申込を再度キャンセルしようとした場合 → エラーを返す

---

## UC3: 運営者がセミナーを作成する

- アクター: 運営者
- 事前条件: なし
- 事後条件（成功時）: セミナーが作成され、申込を受け付けられる状態になる

### 基本フロー
1. 運営者がタイトル・開催日時・定員を入力する
2. システムが入力値を検証する
3. システムがセミナーを作成する

### 例外フロー
- 2a. 定員が1未満の場合 → エラーを返し、作成しない
- 2b. 開催日時が過去日の場合 → エラーを返し、作成しない
